## 인덱스

결론은 인덱스의 철학은 데이터의 저장 성능을 희생하고 데이터 읽기 속도를 높이는 기능이다.

B - tree :  모든 노드에 키 와 값을 적재 하는 구조

Hash :  값을 해싱 해서 인덱싱 하는 구조인데, 전방 일치나 값의 일부만 검색하는것에는 사용이 어렵다. 그래서 메모리 기반의 데이터베이스에서 많이 사용한다.&#x20;

### B - tree

B 는  balacne 라는 뜻이다..&#x20;

인덱스 추가 일때는 적절한 위치를 찾고 주소정보  를 리프노드에 저장 , 저장을 못할정도로 꽉차면 리프노드가 분리 되어야 하는데 이럼 처리 범위가 넓어져서 , 추가 작업은 비용이 많이 든다.&#x20;

**쓰기** 작업에 대한 비용은 기본 1 에 인덱스 키 1.5 정도 되는데 이 비용의 영향은 디스크로부터 인덱스 페이지를 읽고 쓰기를 해야해서 걸리는 시간이다.&#x20;

단 기본키나, 유니크는 중복 체크가 필요하기 떄문에 버퍼를 태우는게 아니라 즉시 추가 및 삭제한다

**삭제**는 이지&#x20;

**변경**은 키값이 변경되면 그에따른 리프노드 위치도 결정되므로 단순히 인덱스 키만 변경하는건 안된다. 먼저 삭제후 , 새로운 키 값으로 추가하는 형태로 한다.&#x20;

검색은 일치 또는 앞부분 만 일치하는 경우에만 사용, 인덱스의 키값에 변형이 가해진 후 비교 되는 경우에는 절대 B - TREE 의 빠른 검색 기능을 이용 할수 없다 . 이미 변형된 값은 B- TREE 인덱스에 존재하는 값이 아니기 때문 , 따라서 함수나 연산을 수행한 결과로 정렬 검색하는 작업은 인덱스 장점을 활용할수 없다 .&#x20;

### 인덱스 키 값의 크기

데이터 저장하는 기장 기본 단위는 페이지 또는 블록. 페이지는 버퍼풀에서 데이터를 버퍼링 하는 기본 단위. 루트 - 브랜치 - 리프 노드를 구분하는 기준이 바로 페이지 단위다. B - tree 에서는 자식 노드가 가변적인 구조 그래서 이진이 아니라는 말이다. 16 KB 기준으로 페이지 단위 일떄&#x20;

인덱스 16바이트 자식노드 주소 12바이트 일떄 16KB 인덱스 페이지 기준 최대 자식노드를 585 개 까지 저장 가능하다.&#x20;

만약 키 값이 늘어나서 한 페이지에 300여개 정도 저장이 된다 치자. 그러면 500개 쿼리가 조회될떄 디스크를 2번 정도 읽어야 한다. 즉 인덱스 가 많아지면 그에따른 키값과 그런것들이 묶여서 읽을수있는 한페이지 덩어리내 갯수가 줄어든다.&#x20;

역시 깊이도 키 값에 따라 달라진다 . 키가 거질수록 깊이 3 기준 2억 개 에서 5천만개가 될수있다.&#x20;

**결국 인덱스의 값의 크기는 가능하면 작게 만드는것을 매우 중요하다 .**

**선택도는 낮은게 좋다. 카디널리트는 높고 선택도는 낮게**



### 인덱스를 통한 데이터 읽기

**인덱스 레인지 스캔 :** 검색해야할 인덱스의 범위가 결정됐을 떄 사용하는 방식이다. 일단 시작해야할 위치를 찾으면 그때부터 리프노드 레코드만 순서대로 읽으면 된다. 만약 끊기면 그 다음링크로 연결된 리프로 간다.&#x20;

뭐가됐든 스캔 시작 위치를 탐색하고 , 그 지점부터 필요한 방향 (asc, desc) 으로 인덱스를 읽어 나가는 과정이다. 어떤 방식으로 스캔을 하든 , 인덱스를 구성하는 칼럼의 정순 또는 역순으로 정렬된 상태로 레코드를 가져온다, 이건 인덱스 자체의 정렬 특성 때문에 그런다.&#x20;

또 검색 조건 일치하는 건들은 데이터 파일에서 레코드를 읽어오는 과정이 필요하다는 것이다. 이떄 레코드 한건한ㄱ선 단위로 랜덤 I/O 가 일어나는데 인덱스를 통해 읽어야할 데이터 레코드가 20%-25% 늘어나면 인덱스를 통한 읽기 보다 테이블의 레코드를 직접 읽는것이 효율적인 처리 방식이 된다.



**인덱스 풀 스캔  :** 인덱스를 처음부터 끝까지 읽는 방식을 풀스캔이라고 한다.&#x20;

쿼리의 조건절에 사용된 칼럼이 인덱스의 첫번쨰 칼럼이 아닌경우 풀스캔 뱅식을 사용 인덱스 레인지 보다는 느리지만 테이블 풀스캔보다는 빠르다.&#x20;

**루스 인덱스 스캔 :** 느슨하게 듬성듬성하게 인덱스를 읽는다.

중간에 필요하지 않는 인덱스 키 값은 무시하고 넘어가는 형태. group by , max 함수에 대해 최적화 하는경우 사용
