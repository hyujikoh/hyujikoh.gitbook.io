# 가비지 컬렉터와 메모리 할당 전략

어떤 메모리를 회수 하나 , 언제 회수 하고 , 어떻게 회수 해야 할까 이게 제일 중요하다 .&#x20;

대상이 죽었는지 확인을 해야 그래야 수집하고 버릴수있다.&#x20;

수집하고 참조하는 객체가 없는 즉 카운팅이 없으면 그 객체는 사용할수없다



자바에서 GC 루트로 할수있는 객체&#x20;

* 가상 머신 스택에서 참조하는 객체 : 현재 실행중인 메서드에 매개변수 지역 변수 임시 변소
* 메서드 영역에서 클래스가 정적 필드로 참조하는 객체
* 메서드 영역에서 상수로 참조되는 객체
* JNI 가 참조하는 객체 , class 객체 , 동기화로 잠겨있는 모든 객체&#x20;





| 종류      | 선언/클래스                | GC 회수 기준                      | 대표 용도                       | 핵심                |
| ------- | --------------------- | ----------------------------- | --------------------------- | ----------------- |
| 강한 참조   | 일반 변수 참조              | 강한 참조가 하나라도 있으면 회수하지 않음       | 일반적인 모든 객체 사용               | 기본 참조             |
| 부드러운 참조 | `SoftReference<T>`    | 메모리가 부족할 때 GC가 회수 가능          | 메모리 민감 캐시                   | “메모리 여유 있으면 유지”   |
| 약한 참조   | `WeakReference<T>`    | 강한/부드러운 참조가 없으면 다음 GC에서 회수 가능 | `WeakHashMap`, 리스너/메타데이터 연결 | “GC가 돌면 사라질 수 있음” |
| 유령 참조   | `PhantomReference<T>` | 객체 회수 직전/후처리 시점 감지용           | 네이티브 리소스 정리, 생명주기 추적        | 객체 접근 불가, 알림만 받음  |





### 가비지 컬렉팅 알고리즘

마크 스윕 : \
회수할 객체를 표시하고 컬렉팅 따로 작업 한게 없고 그나마 바로 진행하고 구현한다. \
단점 : 실행 효율이 일정 치 않고 , 메모리 파편화가 심하다\
\
마크 카피 알고리즘 \
회수할 객체가 많아지면 효율이 떨어지는 위 알고리즘을 해결하기 위해 가용 메모리를 반갈 해서 한쪽만 사용하다 이제 컬력팅 하면 살아남은 객체는 다른 블록에 복사하고 기존 블록을 한번에 청소한다. 대다수의 객체가 회수 된다면 효율이 죽인다. 단 가용 메모리는 절반밖에 못쓴다는 단점이 있다.&#x20;

마크 컴팩트 알고리즘 : \
표시 단계는 마크 스윔과 동일하지만 컴팩트 단계에서 모든 객체 메모리 영역의 한쪽 끝을 모은다음 나머지 공간을 한번에 비운다. 큰 차이는 메모리 이동이 일어난다는 것이다. 단 이 문제에서 살아남은 객체의 참조가 이동되어서 모두 갱신을 해야한다는 점이다. 이동 시키지 않는다면 할당이 빡세고 이동 시키면 회수 작업이 복잡해진다. <br>
