# 자바 메모리 영역과 메모리 오버플로

자동으로 메모리를 관리하는 매커니즘 덕에 c 와같은 메모리 커스텀을 안해도 된다.&#x20;

다만 문제가 터지면 가상 머신의 메모리 관리방식을 이해하지 못하는 한 해결하기 매우 어렵다.

## 런타임 데이터 영역

자바 프로그램을 시동 시키는데 필요한 메모리를 몇개의 ㄷ데이터 영역으로 나눔

이 부분은 목적과 생성/삭제 시점이 다르다&#x20;

모두가 공유 하는 영역 : 메서드 영역 (런타임 상수 풀) , 힙

스레드별 독립적 : 가상 머신 스택 , 프로그램 카운다, 네티이브 메서드 스택

### pc

바이트 코드의 줄 번호 표시기&#x20;

즉 인터프리터는 카운터의 값을 바꾸어 다음에 실행할 바이트코드 명령어를 표시한다 .&#x20;

그래서 스레드 마다 전환 되었을때 어디 까지 처리 되었나를 판단하기 위해 고유한 pc 가 필요함



### 자바 가상 머신 스택

스레드 하나당 JVM 스택 하나가 생성됩니다.

메서드가 호출되면 그 메서드 전용 공간인 _스택 프레임(Stack Frame)_ 이 쌓이고, 메서드가 끝나면 가장 최근 프레임부터 제거됩니다. 즉, 호출 흐름을 자연스럽게 표현하는 LIFO(Last In, First Out) 구조

* 지역변수 테이블  ㅣ데이터 타입 , 객체 참조 , 반환 주소 타입
* 피 연산자 스택&#x20;

스택의 요청한 게 깊이 보다 크다면 sof 발생 , 또한 동적으로 확장하지 못할 정도로 메모리가 충분하지 못하다면 oom 을 던진다



### 자바 힙&#x20;

사용할수 있는 가장 큰 메모리, 모든 스레드가 공유&#x20;

객체 할당 효율을 높이고자 스레드 로컬 할당 버퍼 여러개로 나눈다 . 자바 힙을 다시 작게 구분하는 목적은 메모리 회수와 할당을 더 빠르게 하기 위함

물리적으로 힙은 떨어져 있어도 논리적으로 연속적이여야 한다. 큰 객체는 물리적으로 연속되게 해야 한다. 저장 효율을 높이고 구현 로직을 단순하게 하기 위함

### 런타임  상수 풀&#x20;

* **Method Area**: JVM 명세가 정의한 논리적 영역입니다.
* **Metaspace**: HotSpot JVM이 Java 8부터 Method Area의 상당 부분을 구현하는 네이티브 메모리 영역입니다. 과거 PermGen을 대체했습니다.
* **Runtime Constant Pool**: 클래스 또는 인터페이스마다 생성되는 상수/심볼 참조 테이블입니다. 명세는 이 풀을 Method Area에서 할당한다고 정의합니다.



### 핫스팟 기준 자바 생성&#x20;

1. 생성
2. 로딩 완료 되면 객체를 메모리에 할당한다.
3. 포인터 밀치는 생각보다 복잡하다.&#x20;
4. 적절한 알고리즘과 뭐시기를 해서 처리한다 .&#x20;
