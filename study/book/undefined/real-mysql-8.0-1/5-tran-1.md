# 5장 트랜잭션과 잠금 (원본)

## 트랜잭션과 잠금

트랜잭션은 완전성을 보장해주는게 목표이다.&#x20;

잠금은 여러 커넥션에서 동시에 동일한 자원을 요청할 경우 순서대로 처리하게 해주는 역할

격리수준은 한트랜잭션의 작업이 여러 트랜잭션간 작업 내용을 어떻게 공유하고 차단하는지 결정하는 레벨

결국 중요한건 트랜잭션의 범위를 최소화 하고 , 네트워크 작업이 있는 경우엔 트랜잭션에서 배제 해야한다. 이걸로 인해 선으에 부하를 끼칠수있다.

mysql 엔진 레벨의 잠금은 전체 영향을 주지만 스토리지 엔젠 레벨 잠금은 해당 영역만 하고 스토리지 엔진간 상호 영향을 끼치지 않는다.&#x20;



### mysql 엔진의 잠금&#x20;

* 글로벌 락 : 개빡센 락 , 다른 세션에서는 select 를 제외한 ddl, dml 은 글로벌 락이 해제될때까지 못함
* 백업 락 : 글로벌 락보다 조금 더 가벼운 락 , 일반적인 테이블 데이터 변경은 허용, 보통 cqrs 구성에서 slave 를 동기화 하기 위한 백업락은 이런 목적으로 도입
* 테이블 락 : 거의 글로벌 락과 비슷한 느낌인데 거의 사용안함&#x20;
* 네임드 락 : 임의의 문자열에 대해 잠금을 설정 가능 , 레코드나 db 객체는 아니고 오로지 사용자 지정된 문자열에 대해서만 한다. (디비 서버 한대에 5대 웹서버가 좁속해서 정보 동기화 해야하는 즉 상호동기화를 처리할때 네임드 락을 이용하면 해결할수있지 않을까 싶다. )
* 메타 데이터 락 : 테이블의 이름이나 구조 변경할때 획득하는 락&#x20;

### innoDB 엔진 잠금

레코드 기반 잠금 방식 : inno 는 레코드 자체를 거는게 아니라 인덱스 레코드를 거는것이다. 인덱스가 없는 테이블 도 클러스터 인덱스를 거는 방식&#x20;

갭락 : 레코드 자체가 아니라 레코드와 인접한 레코드 사이 간격만 잠그는것&#x20;

next key lock : 레코드 + 갭락

자동 증가 락 : ai 가 발생될때 동시성을 위해서 락을 검



skip lock&#x20;

인덱스와 락 : 조건 절을 걸때 인덱스가 없는 애들은 해당 되는 전체 테이블 로우 레코드를 스캔할수있다. 또 그것이 잠길수가 있다.&#x20;

왜 inno db 에서는 이걸 시도를 한것인가 고민을 해봐야한다.



### 격리수준

UC : 더티 리드가 존재 한다 .

RC : 동일 트랜잭션에서 조회 할때 새로운 데이터가 나올수있다.&#x20;

RR : 고유 트랜잭션 번호가 있어 그걸 통해 구성이 되어있다. 그래도 이것도 팬텀리드가 나올수있다.&#x20;
